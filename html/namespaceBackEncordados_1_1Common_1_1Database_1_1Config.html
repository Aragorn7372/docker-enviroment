class BackEncordados.Common.Database.Config.MaterialsDbContext ( DbContextOptions< MaterialsDbContext >  options)

DbContext de EF Core para la gestión del catálogo de materiales e insumos de encordados. Administra las tablas Cuerdas (cuerdas/tensores para raquetas) y Materiales (grips, overgrips, lead tape, siliconas y otros accesorios).

Responsabilidades:

  • Configurar el mapeo de las entidades Cuerdas y Material a sus tablas correspondientes.
  • Establecer conversión global de Ulid a string para todas las propiedades del modelo.
  • Aplicar soft-delete mediante HasQueryFilter(u => !u.IsDeleted) en ambas entidades.
  • Configurar timestamps automáticos (CreatedAt, UpdatedAt) a través de ConfigureTimestamps().
  • Poblar datos de semilla para 8 cuerdas y 8 materiales en 5 torneos de prueba.

Entidades administradas:

  • Cuerdas → Tabla Cuerdas: cuerdas para raquetas (poliéster, tripa natural, híbridos, etc.).
  • Material → Tabla Materiales: grips, overgrips, lead tape, siliconas y otros.

Convenciones globales:

  • Conversión automática de Ulid a string mediante UlidToStringConverterNonNullable.
Parámetros
optionsOpciones de configuración del DbContext. Inyectadas a través del contenedor de dependencias (DI) con AddDbContext<MaterialsDbContext>().

Catálogo de cuerdas y tensores para raquetas de tenis. Cada registro representa un modelo específico con marca, formato (reel/set) y tipo de material.

Catálogo de materiales complementarios para raquetas: grips, overgrips, lead tape, siliconas y otros accesorios.

Configura las convenciones globales de propiedades para todo el modelo. Establece que todas las propiedades de tipo Ulid se conviertan automáticamente a string para su almacenamiento en la base de datos.

Esta convención evita tener que decorar cada propiedad Ulid individualmente con HasConversion<UlidToStringConverterNonNullable>() en el mapeo de cada entidad.

Sin esta conversión, EF Core intentaría mapear Ulid como un tipo complejo, lo que causaría errores de esquema en bases de datos relacionales.

Parámetros
configurationBuilderConstructor de configuración de convenciones del modelo. Proporciona métodos fluidos para aplicar convenciones globales a todas las propiedades que coincidan con un tipo o criterio determinado.

Configura el modelo de datos de EF Core para las entidades Cuerdas y Material. Define la estructura de tablas, restricciones de propiedades, conversiones de tipos, filtros de soft-delete, timestamps automáticos e inserta los datos de semilla.

Configuración de Cuerdas (tabla Cuerdas):

  • Clave primaria: Id (tipo long, autogenerado).
  • TournamentId requerido — asocia la cuerda a un torneo.
  • Marca requerido, máximo 100 caracteres.
  • Modelo requerido, máximo 100 caracteres.
  • Stock requerido — cantidad disponible en inventario.
  • Precio requerido — precio unitario en euros.
  • StringFormat requerido — convertido a string desde enum FormatoCuerda (Reel/Set).
  • StringsType requerido — convertido a string desde enum StringsType (Polyester, Multifilament, etc.).
  • Timestamps automáticos via ConfigureTimestamps().
  • Filtro global de soft-delete: HasQueryFilter(u => !u.IsDeleted).

Configuración de Material (tabla Materiales):

  • Clave primaria: Id (tipo long, autogenerado).
  • TournamentId requerido — asocia el material a un torneo.
  • Marca requerido, máximo 100 caracteres.
  • Modelo requerido, máximo 100 caracteres.
  • Stock requerido — cantidad disponible en inventario.
  • Precio requerido — precio unitario en euros.
  • Type requerido — convertido a string desde enum MaterialType (Grip, Overgrip, LeadTape, etc.).
  • Timestamps automáticos via ConfigureTimestamps().
  • Filtro global de soft-delete: HasQueryFilter(u => !u.IsDeleted).

Configuraciones compartidas:

  • Conversión de enums a string para StringFormat, StringsType y Type mediante HasConversion<string>().
  • Inserción de datos de semilla (8 cuerdas + 8 materiales) vía SeedData().
Parámetros
modelBuilderInstancia de ModelBuilder que proporciona la API fluida para configurar el mapeo objeto-relacional de las entidades del dominio.

Inserta datos de semilla en las tablas Cuerdas y Materiales para los 5 torneos de prueba predefinidos. Los datos representan un inventario realista de productos para encordados.

DbContext de EF Core para la gestión de pedidos de encordados. Administra las tablas Pedidos (solicitudes de clientes) y PedidoLineas (detalles individuales de cada raqueta dentro de un pedido).

Responsabilidades:

  • Configurar el mapeo de las entidades Pedidos y PedidoLinea a sus tablas correspondientes.
  • Establecer la relación 1:N entre Pedidos y sus líneas (Lineas → PedidoLineas) con borrado en cascada.
  • Configurar la entidad owned StringSetup como parte de PedidoLinea (tensión y tipo de cuerda en vertical/horizontal).
  • Establecer índices para búsquedas por PlayerId, AssignedTo, PayStatus, PedidoId y Status.
  • Poblar datos de semilla para 8 pedidos con sus líneas y configuraciones de cuerda en 3 torneos de prueba.

Entidades administradas:

  • Pedidos → Tabla Pedidos: solicitudes de encordado con máquina asignada, precio y estado de pago.
  • PedidoLinea → Tabla PedidoLineas: cada raqueta a encordar, con modelo, nudos, colores, logotipo y StringSetup.

Comportamiento especial:

  • El DbSet PedidoLineas usa entidades anónimas para HasData() (sin constructor público de seed).
  • La propiedad estática DisableTransactions permite deshabilitar warnings de transacciones en modo test.

DbContext de EF Core para la gestión de torneos y talleres de encordado. Administra la tabla Tournaments (torneos) y su colección owned WorkerMachineAssignments (asignación de máquinas a trabajadores por torneo).

Responsabilidades:

  • Configurar el mapeo de la entidad Tournaments a la tabla Tournaments.

class BackEncordados.Common.Database.Config.UserDbContext ( DbContextOptions< UserDbContext >  options)

DbContext de EF Core para la gestión de usuarios del sistema. Administra la tabla users con autenticación basada en email/password hasheado con BCrypt y control de concurrencia optimista mediante Version.

Responsabilidades:

  • Configurar el mapeo de la entidad User a la tabla users.
  • Establecer la conversión de Ulid a string para Id (no-nullable) y TournamentId (nullable).
  • Configurar índices únicos en los campos Email y Username.
  • Aplicar control de concurrencia optimista mediante la propiedad Version como token de concurrencia.
  • Aplicar soft-delete mediante HasQueryFilter(u => !u.IsDeleted).
  • Poblar datos de semilla para 9 usuarios (ADMIN, OWNER, ENCORDER×2, USER×4, SUPERVISOR×2) con contraseñas hasheadas.

Características distintivas frente a otros DbContexts:

  • No registra convenciones globales en ConfigureConventions: las conversiones de Ulid se configuran inline en el mapeo de User.
  • Utiliza UlidToStringConverter (nullable) para TournamentId y UlidToStringConverterNonNullable para Id.
  • Incluye IsConcurrencyToken() en la propiedad Version para detección de conflictos de escritura concurrente.
  • Define nombres explícitos de índice: IX_users_email_unique y IX_users_username_unique.
Parámetros
optionsOpciones de configuración del DbContext. Inyectadas a través del contenedor de dependencias (DI) con AddDbContext<UserDbContext>().

Configuración de convenciones globales del modelo. Intencionalmente vacío: las conversiones de tipo se definen inline en el mapeo de User dentro de OnModelCreating.

A diferencia de otros DbContexts del proyecto (MaterialsDbContext, PedidosDbContext, TalleresDbContext), este DbContext no registra una conversión global de Ulid a string. En su lugar, cada propiedad Ulid de User se convierte individualmente usando HasConversion:

  • Id → UlidToStringConverterNonNullable
  • TournamentId → UlidToStringConverter (nullable)
Parámetros
configurationBuilderConstructor de configuración de convenciones del modelo.

Configura el modelo de datos de EF Core para la entidad User. Define la estructura de la tabla users, restricciones de propiedades, conversiones de Ulid, índices únicos, token de concurrencia, timestamps, filtro de soft-delete e inserta los datos de semilla.

Flujo de configuración:

  1. base.OnModelCreating(modelBuilder) — ejecuta configuraciones base de EF Core.
  2. SeedData(modelBuilder) — inserta datos de semilla.

Propiedades configuradas:

  • Username — requerido, máximo 50 caracteres, Unicode false (ASCII). Índice único.
  • Email — requerido, máximo 100 caracteres, Unicode false (ASCII). Índice único.
  • PasswordHash — requerido. Hash BCrypt de la contraseña.
  • Role — requerido, máximo 20 caracteres. Valores: ADMIN, OWNER, ENCORDER, SUPERVISOR, USER.
  • Phone — opcional, máximo 20 caracteres.
  • ImageUrl — requerido, máximo 500 caracteres. URL de avatar en Cloudinary.
