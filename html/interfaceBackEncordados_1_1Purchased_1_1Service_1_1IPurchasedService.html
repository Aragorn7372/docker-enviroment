Descripción detallada

Defines the application-layer service contracts for the Purchased (pedidos) bounded context.

IPurchasedService orchestrates the full lifecycle of purchase orders and their line items. It co operates across multiple infrastructure concerns:

Concern Service(s)
Persistence Repository.IPuchasedRepository, Usuarios.Repository.IUserRepository
Caching Common.Service.Cache.ICacheService (L1 + L2 hybrid, user data and purchased DTOs)
Image resolution Common.Service.Cloudinary.ICloudinaryService for user avatar URLs
Notifications Common.Service.Email.IEmailService, Common.Service.WhatsApp.IWhatsAppService, SignalR hub

All write operations return Result<T,E> with DomainErrors on failure. Read-only queries return DTOs directly (non-Result) — they throw on infrastructure errors. Error types used include: PurchasedNotFoundError, Usuarios.Errors.UserNotFoundError, InvalidStatusError, Usuarios.Errors.UnauthorizedError, Usuarios.Errors.ConcurrencyError.

bool  isUser,
string?  idUser 
)

Cancels an order (and all its line items) with role-based authorization.

Flow:

  1. Call repository.CancelPurchasedAsync — sets order to CANCELED and all lines to CANCELED.
  2. If the caller has USER role (isUser = true), verify PlayerId == idUser; return Usuarios.Errors.UnauthorizedError on mismatch.
  3. Re-cache the updated DTO (5-minute TTL).
  4. Fire-and-forget: send cancellation email, WhatsApp notification, and SignalR broadcast (PEDIDO_CANCELADO).
Parámetros
idThe order Ulid.
isUsertrue if the caller has the USER role, triggering ownership verification.
idUserThe caller's Ulid string, used for the ownership check when isUser is true.
Devuelve
The canceled order DTO or a domain error.

string  status

Changes the status of every non-conflicting line item in an order to the given value.

Conflict rules:

  • When target is CANCELED: lines already COMPLETED or DELIVERED_TOpLAYER are skipped (cannot cancel completed work).
  • When target is any non-canceled status: lines already CANCELED are skipped (cannot revive a canceled line).

After updating all eligible lines, the parent order cache entry is invalidated.

Parámetros
purchasedIdThe order Ulid.
statusThe target status string for all eligible lines.
Devuelve
The updated order DTO or a PurchasedNotFoundError / InvalidStatusError.

◆ ChangeLineaStatusAsync()

Task< Result< PedidoLineaResponseDto, DomainErrors > > BackEncordados.Purchased.Service.IPurchasedService.ChangeLineaStatusAsync ( Ulid  lineaId,
string  status 
)

Changes the status of a single PedidoLinea and sends appropriate notifications.

Flow:

  1. Parse and validate the status string against Status enum.
  2. Load the existing line from the repository.
  3. Persist the status change.
  4. Invalidate the parent order cache.
  5. If new status is COMPLETED: send completion email + WhatsApp to the player.
  6. If new status is DELIVERED_TOpLAYER: send delivery email + WhatsApp to the player.
  7. If new status is CANCELED: send WhatsApp cancellation to the player.
  8. Send ESTATUS_LINEA_PEDIDO_ACTUALIZADA SignalR notification.
Parámetros
lineaIdThe line Ulid.
statusThe target status string (e.g. "PENDING", "IN_PROGRESS", "COMPLETED", "DELIVERED_TOpLAYER", "CANCELED"). Case-insensitive.
Devuelve
The updated line DTO or a domain error.

◆ CreatePurchasedAsync()

Task< Result< PurchasedResponseDto, DomainErrors > > BackEncordados.Purchased.Service.IPurchasedService.CreatePurchasedAsync ( PurchasedRequestDto  request)

Creates a new purchase order with automatic bonus payment logic.

Creation flow:

  1. Lookup player and encorder by username (cache-first, then DB).
  2. Map the request DTO to a Pedidos entity via Mapper.PurchasedMapper.ToEntity(PurchasedRequestDto, Ulid, Ulid).
  3. If player.Bonos >= Price: set PayStatus = PAID, deduct bonus, retry DB update up to 3 times (PurchasedService.UpdateUserWithRetryAsync).
  4. If 0 < player.Bonos < Price: append a shortfall comment ("Falta por pagar: ...").
  5. Persist the aggregate via the repository.
  6. Cache the resulting DTO (5-minute TTL).
  7. Fire-and-forget: send SignalR notification (PEDIDO_CREADO to tournament group + admin group).
  8. If auto-paid: enqueue a payment confirmation email to the player.

Requires [Transactional(typeof(PedidosDbContext), typeof(UserDbContext))] at the controller level for distributed consistency.

Parámetros
requestThe order creation payload (tournament, player/encorder usernames, line items, price, payment status).
Devuelve
The created order DTO or a Usuarios.Errors.UserNotFoundError if the player or encorder could not be found.

◆ FindAllAsync()

Task< PageResponseDto< PurchasedResponseDto > > BackEncordados.Purchased.Service.IPurchasedService.FindAllAsync ( FilterPurchasedDto  filter)

Returns a paginated list of orders according to the supplied filter, with player and encorder user data resolved.

Orchestration flow:

  1. Call repository FindAllAsync to get the page of order headers and total count.
  2. Collect all unique PlayerId and AssignedTo values from the result set.
  3. Attempt to resolve each user ID from the L1/L2 cache (key: CacheKeys.UserDataKey + id).
  4. For cache misses, batch-fetch from IUserRepository.FindByIdsAsync, cache each result (10-minute TTL).
  5. Map each order through Mapper.PurchasedMapper.ToDto(Pedidos, Usuarios.Dto.UserResponseDto, Usuarios.Dto.UserResponseDto).
  6. Skip orders whose player or encorder could not be resolved (logged as warning).
  7. Return a PageResponseDto<PurchasedResponseDto> with pagination metadata.
Parámetros
filterPagination, sort, and search parameters from the query string.
Devuelve
A PageResponseDto<PurchasedResponseDto> with resolved user DTOs and pagination metadata.
