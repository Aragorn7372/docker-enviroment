Descripción detallada

Atributo de filtro de acción que coordina transacciones en múltiples DbContexts con detección híbrida de errores (excepciones HTTP y Result.Failure vía status codes).

Implementa un patrón de transacción distribuida manual (coordinada) sobre DbContexts independientes que comparten la misma base de datos SQL Server. No utiliza DistributedTransactionCoordinator (MSDTC), sino que inicia transacciones separadas y las confirma/revierte al unísono.

Flujo de ejecución:

  1. Inicializa una lista vacía de transacciones.
  2. Para cada DbContext configurado, obtiene la instancia del DI, verifica si es InMemory (salta), e inicia BeginTransactionAsync.
  3. Ejecuta la acción del endpoint mediante next().
  4. Detecta error: excepción no manejada O status code HTTP ≥400 en la respuesta.
  5. Sin error → Commit de todas las transacciones en orden.
  6. Con error → Rollback en orden inverso (para evitar deadlocks), con try/catch individual por si falla un rollback.
  7. En finally → DisposeAsync de todas las transacciones (liberación garantizada).

Casos especiales:

  • InMemory Database: Durante desarrollo/tests, las bases de datos en memoria no soportan transacciones. Se saltan con log Debug.
  • Rollback parcial: Si un rollback falla (ej: conexión perdida), se loggea el error y se continúa con las demás transacciones.

Detección híbrida de errores (HasResultFailure):

  • Excepción no manejada en context.Exception → rollback.
  • ObjectResult con StatusCode ≥ 400 → rollback.
  • BadRequestResult (400), NotFoundResult (404) → rollback.
  • StatusCodeResult con código ≥ 400 → rollback.
  • Cualquier otro resultado (2xx, 3xx) → commit.

Uso: [Transactional(typeof(PedidosDbContext), typeof(UserDbContext))]
