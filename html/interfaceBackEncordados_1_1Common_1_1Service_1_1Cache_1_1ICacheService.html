Descripción detallada

Define el contrato para los servicios de caché del sistema, soportando una estrategia de dos niveles (L1 local + L2 distribuido).

El sistema de caché implementa una arquitectura híbrida con tres implementaciones:

Nivel Implementación Propósito
L1 MemoryCacheService Memoria local del proceso, acceso ~0.1ms, volátil por instancia
L2 CacheService (Redis) Caché distribuida compartida entre instancias, acceso ~1-5ms
Híbrido HybridCacheService Combina L1+L2 con read-through (GetAsync) y write-through (SetAsync)

Estrategia transversal:

  • GetAsync: Read-through. Consulta L1 primero, luego L2 con backfill a L1.
  • SetAsync: Write-through. Escribe en ambos niveles simultáneamente. TTL default: 5 minutos.
  • RemoveAsync: Elimina de ambos niveles. Seguro si la clave no existe.
  • RemoveByPatternAsync: Elimina por patrón solo en L2. L1 (memoria) no expone sus claves para escaneo.

Todos los métodos de implementación (L2) envuelven operaciones en try/catch con logging para garantizar tolerancia a fallos: si Redis no responde, se retorna default y se registra el error, sin propagar la excepción al llamante.

◆ RemoveByPatternAsync()

Task BackEncordados.Common.Service.Cache.ICacheService.RemoveByPatternAsync ( string  pattern)

Elimina todas las entradas cuyas claves coincidan con un patrón.

Esta operación solo está disponible en implementaciones que soporten búsqueda por patrón (Redis L2 mediante SCAN/DEL). En MemoryCacheService (L1) es un no-op porque Microsoft.Extensions.Caching.Memory.IMemoryCache no expone sus claves internas.

El patrón sigue la sintaxis Redis: "users:*", "torneos:activos:*".

Parámetros
patternPatrón de búsqueda estilo Redis (ej: "prefix:*").
