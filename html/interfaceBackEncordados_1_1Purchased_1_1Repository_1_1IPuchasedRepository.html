Descripción detallada

Defines data-access contracts for the Purchased (pedidos) aggregate, covering both top-level order operations and line-level (PedidoLinea) operations.

IPuchasedRepository is the sole repository for the Pedidos aggregate. It handles:

Category Methods
Query (order) FindAllAsync, FindByIdAsync
Command (order) CreatePurchasedAsync, UpdatePurchasedAsync, CancelPurchasedAsync, ChangeStatusPurchasedAsync
Query (line) FindLineaByIdAsync
Command (line) CreateLineaAsync, UpdateLineaAsync, ChangeLineaStatusAsync
Flush SaveChangesAsync

All query methods use AsNoTracking() for read performance. Write methods that accept FilterPurchasedDto support pagination, sorting, and composite filtering (by encorder, player, tournament, and free-text search on comments/machine/raquet model).

Note: The interface name preserves the original typo (IPuchasedRepository instead of IPurchasedRepository) for backward compatibility with DI registrations.

◆ FindAllAsync()

Task<(IEnumerable< Pedidos > Items, int TotalCount)> BackEncordados.Purchased.Repository.IPuchasedRepository.FindAllAsync ( FilterPurchasedDto  filter)

Returns a paginated, filtered, and sorted list of Pedidos together with the total count of matching records.

Filtering logic:

  • Encorder filter — if IsEncorder == true, filters by AssignedTo == UserId.
  • Player filter — if IsUser == true, filters by PlayerId == UserId.
  • Tournament filter — optional exact match on TournamentId.
  • Search — free-text match against Comments, Machine, and line-level RaquetModel (via LIKE).
  • Sorting — by CreatedAt, Machine, PlayerId, AssignedTo (as "encorder"), or default by Id.

After pagination, associated PedidoLinea items are loaded in a second query using a batch WHERE PedidoId IN (...) to avoid N+1.

Parámetros
filterPagination (Page, Size), sort (SortBy, Direction), and filter (UserId, IsEncorder, IsUser, TournamentId, Search) parameters.
Devuelve
A tuple containing the page items (with line items populated) and total element count across all pages.
