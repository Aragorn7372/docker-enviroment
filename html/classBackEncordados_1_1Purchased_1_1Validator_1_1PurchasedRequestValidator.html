Descripción detallada

Validates a PurchasedRequestDto before a purchase order is created.

This validator performs the following cross-cutting validation steps:

  1. Tournament validation — verifies the tournament exists in the database and has not been soft-deleted (IsDeleted == false).
  2. Player validation — looks up the PlayerName by username (cache-first, then DB). Rejects if the user does not exist, is deleted, or does not have the USER role. On success, stores the resolved User in RootContextData["PlayerUlid"].
  3. Encorder validation — looks up the AssignedToName by username. Rejects if the user does not exist, is deleted, or does not have the ENCORDER or OWNER role. Stores the resolved User in RootContextData["AssignedToGuid"].
  4. Payment status validation — ensures the PayStatus string matches one of the PaymentStatus enum values (case-insensitive).
  5. Line items validation — ensures at least one line item exists and delegates each item to PedidoLineaRequestValidator.

The resolved User objects stored in RootContextData are consumed by the controller or service layer to avoid redundant database lookups after validation passes.
